# `person_tracker` 추적 · 재식별 · 3D 위치 추정 알고리즘 설명

`person_tracker`가 사람 검출 결과를 받아 **외형 특징을 추출하고, 타겟 ID를 유지·재식별하며, 2D LiDAR와 정합해 3D 좌표를 계산**하는 전체 알고리즘 원리를 정리한 문서입니다.

---

## 전체 파이프라인 요약

```text
[상단 카메라 영상]
   │
   ▼
[1단계] YOLO 탐지 + 내장 모션 트래커 (ByteTrack / BoT-SORT)
   │   └─ 모델/트래커 전환 시 0.65×IoU + 0.35×ReID로 타겟 자동 승계
   ▼
[2단계] 태스크별 픽셀 샘플링 & HSV(+밝기 V) 특징 추출 (PartFeatureBank)
   │   ├─ Detect : 박스 중앙 비율 3등분
   │   ├─ Segment: 폴리곤 실루엣 + 3×3 침식 후 3등분
   │   └─ Pose   : COCO 17개 관절 기반 몸통/허벅지/정강이 마스킹
   ▼
[3단계] 5종 추적 모드 + 3D 공간 게이팅 (기본: Adaptive SAFE/GUARD/SEARCH)
   │   └─ 겹침 시 타인 영역 마스킹(exclude_boxes) + 물리 이동 반경 점수 결합
   ▼
[4단계] 핀홀 수평각 계산 + 2D LiDAR 거리 정합 + TF2 좌표계 변환
       └─ base_link / map 좌표 출력 (LiDAR 미매칭 시 카메라 핀홀 거리 백업)
```

## 1단계: YOLO 사람 탐지 및 기본 트래킹 (`multi_tracker_core.py`)

### 1) 어떻게 사람을 탐지하는가? (YOLO Detect / Segment / Pose)
매 프레임 `self.model.track(frame, persist=True, classes=[0], imgsz=320, conf=0.15, iou=0.55, ...)`가 실행됩니다.
1. **단일 패스(One-shot) CNN 추론**: 입력 영상(`640×480`)을 `imgsz=320` 크기로 레터박스 리사이즈한 뒤 신경망을 한 번 통과시켜, 후보 바운딩박스 `(x1, y1, x2, y2)`와 클래스 신뢰도(Confidence)를 동시에 예측합니다.
2. **사람 클래스 필터링 & NMS**:
   - COCO 80개 클래스 중 `classes=[0]`(**person**)만 남기고, 신뢰도 `conf < 0.15`인 약한 후보를 걸러냅니다.
   - 한 사람 주변에 겹쳐 나온 여러 박스는 **`iou=0.55` NMS(Non-Maximum Suppression)** 로 가장 확률 높은 박스 1개만 남깁니다.
3. **태스크별 추가 출력**:
   - **Detect**: 바운딩박스만 출력
   - **Segment**: 박스 + 사람 픽셀 윤곽 폴리곤(`masks.xy`, `retina_masks=False`) 출력
   - **Pose** *(기본)*: 박스 + COCO 17개 관절 좌표·신뢰도(`keypoints.data`) 출력

### 2) 어떻게 프레임 간 사람을 추적하는가? (1층: ByteTrack / BoT-SORT)
YOLO 자체는 매 프레임 독립적으로 사람만 찾기 때문에 "이전 프레임의 1번이 이번 프레임의 몇 번 박스인지" 모릅니다. 이를 이어 `track_id`를 유지하는 역할이 내장 모션 트래커입니다.

1. **기본 추적 사이클 (칼만 필터 + 헝가리안 매칭)**:
   - **예측(Predict)**: 기존 `track_id`마다 등속도 칼만 필터로 "이전 위치·속도로 볼 때 이번 프레임엔 어디 있을지" 예측 박스를 먼저 계산합니다.
   - **매칭(Associate)**: 예측 박스와 이번 프레임 YOLO 검출 박스들 사이의 **IoU(겹침 비율)**를 계산해 최적 1:1 매칭(헝가리안 알고리즘)을 수행합니다.
   - **갱신(Update)**: 매칭된 박스로 칼만 필터 상태를 보정해 같은 `track_id`를 이어가고, 일정 프레임 이상 못 찾은 트랙은 삭제합니다.
2. **`ByteTrack` vs `BoT-SORT` 차이**:
   - **`ByteTrack`** *(모드 1, 2, 5)*: 신뢰도가 높은 박스(`high`)와 1차 매칭 후, 못 찾은 트랙은 버리지 않고 **신뢰도가 낮은 박스(`low`, 일부 가려진 사람)와 2차 IoU 매칭**을 한 번 더 시도해 추적 끊김을 줄입니다.
   - **`BoT-SORT`** *(모드 3, 4)*: 로봇이 회전할 때 배경 전체가 밀려 IoU 예측이 어긋나는 문제를 줄이기 위해 **`sparseOptFlow` 기반 카메라 움직임 보정(GMC)** 으로 예측 박스를 먼저 보정하고, 자체 외형 ReID(`with_reid=True`, `appearance_thresh=0.65`, `track_buffer=90`)까지 결합합니다.

### 3) 왜 2층(커스텀 `hist` ReID + 3D 공간 게이팅)을 얹었는가?
- `ByteTrack`은 위치/IoU만 보기 때문에 **두 사람이 겹쳐 스쳐 지나가거나, 화면 밖으로 나갔다 다시 들어오면 `track_id`가 바뀌거나 다른 사람에게 넘어갈 수(ID Switch) 있습니다.**
- 그래서 1층 트래커가 후보 박스와 초기 ID를 뽑아주면, **2층(우리 코드: 2단계 `PartFeatureBank` HSV+V 히스토그램 + 3단계 `Adaptive`·공간 게이팅)**이 *"내가 지정한 진짜 타겟 1명"*을 끝까지 검증하고 복구합니다.

### 4) 실시간 모델·트래커 전환 시 타겟 승계 (`pending_tracker_rebind`)
- `YOLOv8n / 11n / 26n` × `Detect / Segment / Pose` 또는 `ByteTrack ↔ BoT-SORT`를 전환하면 내부 `track_id`가 초기화됩니다.
- 전환 직후 첫 프레임에서 직전 타겟과 새 후보들을 **`0.65 × IoU + 0.35 × 외형유사도`**로 비교해 점수가 `0.25` 이상이면 새 `track_id`로 타겟을 1회 자동 승계합니다.

## 2단계: 태스크별 외형 특징 추출 (`feature_extractors.py`)

`Detect / Segment / Pose`는 **특징을 뽑을 픽셀을 샘플링(마스킹)하는 방식**만 다르며, 이후 반환하는 `PartFeatureBank` 구조(`full`, `upper`, `mid`, `lower`)와 비교 연산은 동일합니다.

### 1) 태스크별 픽셀 마스킹 전략 (Strategy Pattern)
| 태스크 | 추출기 클래스 | 영역 샘플링 및 `upper / mid / lower` 분할 기준 |
| :--- | :--- | :--- |
| **Detect** | `BBoxFeatureExtractor` | 배경을 피하기 위해 좌우 20%, 상단 12%, 하단 8%를 제외한 중앙 사각형을 높이 `38% / 72%`에서 3등분 |
| **Segment** | `SegMaskFeatureExtractor` | YOLO 폴리곤 실루엣(`mask_poly`) 내부만 채우고 3×3 침식(`erode`)으로 경계 배경을 제거한 뒤 높이 `35% / 70%`에서 3등분 |
| **Pose** *(기본)* | `PoseKeypointFeatureExtractor` | COCO 17개 관절(`conf ≥ 0.35`, 선 두께 `max(6, bw × 0.22)`)로 실제 신체 부위만 마스킹:<br>• `upper`: 어깨(5, 6)–골반(11, 12) 몸통 다각형 (`fillPoly`)<br>• `mid`: 골반→무릎(11→13, 12→14) 선분 (`cv2.line`)<br>• `lower`: 무릎→발목(13→15, 14→16) 선분<br>• `full`: 위 세 마스크의 OR 합집합 |

> 세 추출기 모두 공통으로 **`inRange([0, 0, 15], [180, 255, 255])`** 필터로 극단적 암부 노이즈만 걸러내고, 혼잡 상황에서는 `_apply_exclude_boxes()`로 다른 사람 박스와 겹치는 픽셀을 `0`으로 지워 외형 오염을 막습니다.

### 2) HSV 히스토그램 구성 (`18×16`, `16`)과 외형 유사도 정의
- **H-S 2D 히스토그램 (`[18, 16]`)**: OpenCV `H(0~179)`를 `18`칸(10단위 = 20° 간격), `S(0~255)`를 `16`칸(16단위 간격)으로 양자화한 `288`차원 분포입니다. 너무 세밀하면 조명에 민감해지고 너무 성기면 옷 색을 구별 못 하므로 `18×16` 해상도를 사용합니다.
- **V 1D 히스토그램 (`[16]`)**: `S` 하한을 `0`으로 열어 검정·흰색·회색 같은 **무채색 옷도 구분**할 수 있게 밝기(`V`, `0~255`)를 `16`칸으로 따로 뽑습니다.
- **L1 정규화 + 가중 결합 (304차원)**:
  - `H-S`와 `V`를 각각 합이 `1.0`이 되도록 `NORM_L1` 정규화하여(거리에 따른 박스 크기 차이 무시) **`[0.72 × HS, 0.28 × V]`** 로 합칩니다 (`288 + 16 = 304`차원, 전체 합 `1.0`).
- **유사도 계산 (`hist_sim`)**:
  - 두 히스토그램의 겹침 정도를 재는 Bhattacharyya 거리(`cv2.HISTCMP_BHATTACHARYYA`, `0~1`)로 **`유사도 = max(0.0, 1.0 - 거리)`**를 계산합니다.

### 3) `compare_banks` 및 이중 뱅크(`anchor` / `recent`)
`compare_banks(ref, cur)`는 다음 후보들 중 **최댓값(`max`)**을 유사도로 반환합니다.
1. **`aligned_score` (부위별 1:1 매칭)**: 양쪽 다 보이는 부위만 골라 **`upper(0.35)`, `mid(0.40)`, `lower(0.25)`** 가중 평균
2. **`full_score` (전체 매칭)**: `ref.full` vs `cur.full`
3. **교차 부위(Cross-Part) 매칭**: 로봇에 바짝 다가와 상반신이 잘리고 바지·다리만 찍힐 때도 인식되도록 `ref.mid vs cur.full (×0.95)`, `ref.lower vs cur.full (×0.92)`, `ref.mid vs cur.upper (×0.95)`까지 비교

또한 타겟 지정 시 원본(`anchor_bank`)은 고정해 두고 최근 상태(`recent_bank`)만 지수이동평균(`alpha=0.04`)으로 천천히 갱신해, **조명·각도 변화에는 적응하면서 타인으로 서서히 오염되는 드리프트를 방지**합니다(`compute_dual_similarity = max(anchor 유사도, recent 유사도)`).

## 3단계: 5종 추적 모드 및 3D 공간 게이팅 (`multi_tracker_core.py`)

### 1) 5가지 추적 모드
| 모드 | 구성 | 특징 |
| :--- | :--- | :--- |
| `1: ByteTrack` | 내장 ByteTrack | 순수 모션/IoU 추적 |
| `2: Task-ReID` | ByteTrack + `hist` ReID + 공간 게이팅 | 매 프레임 유사도 검사 및 이탈 시 재매칭 |
| `3: BoT-SORT` | 내장 BoT-SORT (`with_reid=True`) | 내장 카메라 보정 + 내장 ReID만 사용 |
| `4: BoT+ReID` | BoT-SORT + `hist` ReID + 공간 게이팅 | BoT-SORT 위에 커스텀 부위/공간 재식별 결합 |
| **`5: Adaptive`** *(기본)* | ByteTrack + 상황별 상태 전환 | **`SAFE` / `GUARD` / `SEARCH`** 3단계 자동 전환 |

### 2) `Adaptive` 모드 상태 전이
- **`SAFE` (단독 추적)**: 주변에 인접한 사람이 없으면 타겟 1명의 유사도만 확인해 연산량을 줄이고, 단독 검출 & `sim ≥ 0.72`일 때만 `recent_bank`를 갱신합니다.
- **`GUARD` (혼잡·겹침 방어)**: 타인 박스와 `IoU > 0.02`이거나 중심이 가까워지면(`_is_crowded_near_target`) 발동합니다.
  - 다른 사람 박스 영역을 `exclude_boxes`로 마스킹한 뒤 모든 후보를 **`0.60 × 외형유사도 + 0.40 × 공간점수`**로 재평가합니다.
  - 현재 `track_id`에는 `+0.04` 관성 보너스를 주되, **라이다/맵상 직전 위치 대비 `0.90 m` 초과 급점프 시 보너스를 제거**해 옆 사람으로 ID가 넘어가는 현상을 막습니다.
- **`SEARCH` (이탈 재탐색)**: 현재 프레임에서 타겟이 사라지면 전체 후보를 `0.65 × 외형 + 0.35 × 공간점수`로 비교해 기준(`reid_match_thresh=0.52`) 통과 시 `RECOVERED`로 복구합니다.

### 3) 3D 공간 게이팅 (`_compute_spatial_score`)
- 직전 확인된 타겟의 `map`(또는 `base_link`) 좌표와 경과 시간 `dt`(8초 이내)로 사람 보행 속도 기준 **허용 반경 `0.65 + 1.35 × min(dt, 6.0)` (m)**를 계산하고, 가우시안 감쇠 점수를 부여합니다.
- 특히 `source == 'LiDAR'` 실측 거리가 허용 반경의 `1.4배`를 넘으면 점수에 `×0.20` 페널티를 주어, **멀리 있는 비슷한 옷차림의 다른 사람으로 튀는 오매칭을 차단**합니다.

## 4단계: 2D LiDAR 정합 및 3D 좌표 변환 (`lidar_person_localizer.py`)

### 1) 핀홀 카메라 모델 기반 수평각(`αc`) & 탐색 반폭 계산
```text
카메라 중심 ----(초점거리 fx)----▶ 화면 정중앙 (W/2)
     \                             |
      \  수평각 αc                 | dx = cx - W/2
       \                           ▼
        -----------------------▶ 타겟 중심 (cx)
```
- 화면 가로 폭 `W`와 수평 화각 `hfov`(기본 `65°`)로 직각삼각형 관계 `tan(hfov/2) = (W/2) / fx`를 이용해 픽셀 단위 초점거리 **`fx = (W/2) / tan(hfov/2)`**를 구합니다.
- 타겟 중심 `cx`가 화면 중앙에서 떨어진 픽셀 `dx = cx - W/2`로부터 **`αc = atan2(-dx, fx)`** (ROS 좌표계 기준 왼쪽 `+`, 오른쪽 `-`)를 계산합니다.
- 박스 좌우 끝(`x1`, `x2`) 각도 차이 `bbox_span = |α_left - α_right|`가 실제 사람이 시야에서 차지하는 수평 각도 폭입니다. 양 끝 빈 배경을 피하기 위해 **`bbox_span × 0.35` (중심 70% 구간)**를 탐색 반폭(`half_sector`)으로 삼고, 최소 `3.5°` ~ 최대 `18.0°`로 제한합니다.

### 2) LiDAR 레이 클러스터 매칭 (`source='LiDAR'`) & 백업 추정 (`CamEst`)
- **TF 변환**: 라이다(`rplidar_link`)와 상단 카메라(`top_cam_link`)의 장착 위치·회전(`+90°` 등)이 다르므로, 최근 `2.5s` 이내의 `/scan` 점군을 `TF(top_cam_link ← rplidar_link)`로 변환한 뒤 전방(`x > 0.12m`) & 섹터(`|β - αc| ≤ half_sector`) 안의 레이들을 추려냅니다.
- **`p25` 클러스터 평균 근거**: 섹터 안에는 사람 몸통뿐 아니라 사람 옆/다리 사이로 빠져나가 **뒷벽에 맞은 먼 레이**도 들어옵니다. 단순 평균은 벽 때문에 거리가 길어지고, 최솟값(`min`)은 노이즈 1점에 튑니다. 따라서 **가까운 하위 25분위(`p25`) 주변 `[p25 - 0.15m, p25 + 0.25m]` 클러스터 평균**을 거리 `cam_dist_m`로 사용합니다.
- **카메라 백업 추정 (`source='CamEst'`)**: 섹터 내 LiDAR 포인트가 없으면 성인 평균 근사 키 `1.65 m`와 핀홀 비례식 **`clip((1.65 × fy) / bbox_h, 0.35, 8.0) m`**로 거리를 백업 계산합니다.

### 3) 로봇 · 맵 좌표계 변환 (`cam_xyz → base_link → map`)
- 카메라 평면 좌표 `(d·cos αc, d·sin αc, 0)`를 `TF(base_link ← top_cam_link)`로 로봇 중심 좌표로 변환한 뒤, `TF(map ← base_link)`(AMCL 우선, 미수신 시 `initial_pose + odom` 변화량 적분 fallback)로 최종 지도 좌표를 발행합니다.
